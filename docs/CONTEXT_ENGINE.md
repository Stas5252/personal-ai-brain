## 1. Строгая иерархия сборки промпта

Порядок следования компонентов в промпте критически влияет на поведение модели. Вышестоящие слои обладают приоритетом над нижестоящими.

### Иерархия сборки:
```
1. SYSTEM POLICY          (Универсальная системная политика, правила безопасности)
       |
2. SPECIALIZED FOCUS      (Целевой фокус агента от Agent Router)
       |
3. USER PROFILE           (Динамический профиль автора: ниша, город, цены, стоп-слова)
       |
4. PROJECT CONTEXT        (Текущий проект, задачи, дедлайны, принятые решения)
       |
5. CLIENT CONTEXT         (Данные конкретного заказчика: бюджет, предпочтения, статус)
       |
6. STYLE DIRECTIVES       (Ритм, длина предложений, эталоны GOOD EXAMPLES)
       |
7. RELEVANT MEMORIES      (Взвешенные факты долговременной памяти)
       |
8. KNOWLEDGE CHUNKS       (Точные цитаты из базы знаний с метаданными)
       |
9. CONVERSATION QUERY     (Текущий вопрос / реплика пользователя)
```

**Ключевой принцип безопасности и гибкости:** в системной политике нет ни единого захардкоженного личного факта. Все персональные сведения подставляются исключительно на уровне `USER PROFILE`, что позволяет мгновенно менять профиль без модификации кода.

## 2. Формула ранжирования элементов контекста

Каждый кандидат на включение в контекст оценивается функцией `rank_items`:

$$\text{Context Score} = 0.45 \cdot \text{Relevance} + 0.35 \cdot \text{Importance} + 0.20 \cdot \text{Recency}$$

Элементы с наивысшим скором первыми занимают доступный лимит токенов.

## 3. Квотирование бюджета токенов (Token Quotas)

Чтобы контекстное окно не переполнялось и сохранялся баланс между памятью, знаниями и инструкциями, Context Engine реализует квотирование:

| Сегмент контекста | Целевой объем (токенов) | Максимальная квота (токенов) | Поведение при превышении |
| :--- | :---: | :---: | :--- |
| **System Policy & Focus** | $300 - 400$ | $600$ | Фиксированный размер |
| **User Profile** | $250 - 300$ | $500$ | Включение ключевых атрибутов |
| **Project Context** | $200 - 400$ | $600$ | Отсечение завершенных задач |
| **Client Context** | $200 - 400$ | $600$ | Отсечение архивных комментариев |
| **Style Directives & Exemplars** | $400 - 500$ | $800$ | Включение топ-2 эталонов |
| **Relevant Memories** | $400 - 600$ | $1000$ | Включение топ-5 по скорингу |
| **Knowledge Chunks** | $800 - 1200$ | $2000$ | Включение топ-4 чанков со сносками |
| **Query & Dialog Buffer** | $300 - 600$ | $1000$ | Скользящее окно последних сообщений |
| **ИТОГО КОНТЕКСТ** | **~3000** | **~7100** | **Комфортно вписывается в окно модели** |

---

## 4. Изоляция контекста проектов и клиентов

Контекстный движок исключает утечку данных между проектами и клиентами:
- При передаче `project_id` в сборщик включаются задачи и решения **только** указанного проекта.
- При передаче `client_id` включаются предпочтения и бюджет **только** данного заказчика.
- Воспоминания и документы базы знаний с чужими `project_id` / `client_id` жестко фильтруются на этапе ретривала.
