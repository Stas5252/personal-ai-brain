# Brain Intelligence Architecture (Архитектура персонального AI-мозга фотографа)

## 1. Концепция и архитектурная парадигма
**Personal AI Brain** — это не универсальный чат-бот, а специализированная операционная система работы фотографа.
Она связывает в единый реактивный контур контекст личности, память прошлых решений, базу знаний, состояние клиентов и проектов с исполнительным движком задач и воркфлоу.

## 2. Ключевые компоненты

### 2.1. User Profile & Tone
- Хранит персональные атрибуты фотографа: имя, нишу, жанры съемок, перечень услуг, ценовую архитектуру, описание идеального клиента, географию и личные табу.
- Ограничивает словарь запрещенными стоп-словами (`forbidden_words`).

### 2.2. Memory Engine & Admission Policy
- Отделяет долговременные ценные факты (предпочтения по свету, ключевые договоренности, бизнес-цели) от временного спама.
- Автоматическая оценка каждого входящего сообщения на предмет сохранения (`AdmissionAction.SAVE` vs `DISCARD`).

### 2.3. Canonical Knowledge Factory & RAG
- Единственный источник истины по методическим материалам, чек-листам, пресетам и гайдам.
- Гибридный поиск: Reciprocal Rank Fusion между семантическими векторами ChromaDB и полнотекстовым поиском SQLite FTS5.
- Точная трассируемость цитат с номерами страниц, слайдов, строк таблиц и таймкодов.

### 2.4. Style Engine & Provenance
- Анализирует реальные тексты пользователя с разделением на категории (`APPROVED_OUTPUT`, `MESSAGE`, `POST`).
- Оценивает сгенерированные черновики по 4 метрикам: лексическое сходство, ритмика предложений, плотность эмодзи, наличие мягкого CTA.

### 2.5. Client & Project Entities
- Клиенты поддерживают полный жизненный цикл: `LEAD` $\to$ `CONTACTED` $\to$ `INTERESTED` $\to$ `PROPOSAL` $\to$ `THINKING` $\to$ `BOOKED` $\to$ `SHOOTING` $\to$ `COMPLETED` $\to$ `FOLLOW_UP` $\to$ `REPEAT` $\to$ `LOST`.
- Проекты отслеживают состояние съемочного продакшна: `IDEA` $\to$ `PLANNED` $\to$ `BOOKED` $\to$ `PREPARATION` $\to$ `SHOOTING` $\to$ `EDITING` $\to$ `DELIVERY` $\to$ `COMPLETED` $\to$ `FOLLOW_UP`.

### 2.6. Task & Workflow Engine
- Унифицированная модель задачи `Task`: статус (`TODO`, `IN_PROGRESS`, `WAITING_APPROVAL`, `COMPLETED`), приоритет (`LOW`, `MEDIUM`, `HIGH`, `URGENT`), привязка к проекту и клиенту, входы/выходы и статус утверждения.
- Многошаговые stateful воркфлоу с контролем шагов, сохранением контекста в SQLite и шлюзами одобрения (`Approval Gates`) для критических операций (отправка сообщений, изменение прайса).

### 2.7. Specialized Domain Engines
1. **ContentEngine**: Скорая помощь «Мне нечего выложить», генерация сценариев Reels с динамичными хуками, цепочки Stories, спринт-планы на неделю.
2. **SalesEngine**: Разбор переписок, диагностика истинных причин сомнений, отработка возражений («дорого», «не умеем позировать», «подумаем»), аудит каннибализации прайс-листа и позиционирования.
3. **ShootingEngine**: Визуальная логика, световые схемы, HEX-палитры, поминутные тайминги и шот-листы съемок, декомпозиция референсов, памятки клиентам.
4. **VoiceEngine**: Превращение голосовых заметок фотографа в структурированные бизнес-активы (1 пост + 2 Reels + 5 Stories + 1 задача).
5. **ProactiveEngine**: Ежедневное планирование («Что мне сегодня делать?»), приоритизация 3 ключевых задач дня, деликатные проактивные уведомления с учетом тихих часов (22:00 - 09:00).

## 3. Политика безопасности и честности
1. **Zero Simulation**: Никаких фальшивых результатов зрения или веб-поиска. Если физический модуль или VLM не сконфигурированы, система честно возвращает статус `NOT_IMPLEMENTED`.
2. **Мандатная авторизация**: Доступ ко всем эндпоинтам защищен Bearer API Key с проверкой `hmac.compare_digest`.
3. **Изоляция клиентов**: Данные одного клиента никогда не смешиваются с материалами другого.
4. **Защита от промпт-инъекций**: Документы базы знаний интерпретируются исключительно как `DATA`, а не как системные инструкции `SYSTEM`.
