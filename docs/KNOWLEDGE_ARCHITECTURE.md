# Personal AI Brain: Иерархическая база знаний (Knowledge Engine & RAG)

**Проект:** Персональный AI-ассистент фотографа и визуального креатора  
**Модуль:** Knowledge Engine (`src/brain/engines/knowledge_engine.py`)  
**Статус:** Реализован и верифицирован (4/4 тестов группы Knowledge: 100% PASS)

## 1. Концепция многослойных знаний

В отличие от классических плоских RAG-систем, где все документы свалены в общий векторный индекс, Knowledge Engine организует знания визуального эксперта в **6 иерархических слоев**.

Это исключает смешивание общих законов физики света с коммерческими условиями съемки или приватными предпочтениями конкретного заказчика.

```
       +-------------------------------------------------------------+
       | L1. GLOBAL LAYER (Фундаментальная теория фотографии, физика) |
       +-------------------------------------------------------------+
                                      |
       +-------------------------------------------------------------+
       | L2. PROFESSIONAL LAYER (Схемы света, оптика, позирование)    |
       +-------------------------------------------------------------+
                                      |
       +-------------------------------------------------------------+
       | L3. PERSONAL LAYER (Авторский манифест, почерк, биография)   |
       +-------------------------------------------------------------+
                                      |
       +-------------------------------------------------------------+
       | L4. BUSINESS LAYER (Прайс-листы, пакеты, договоры, условия)  |
       +-------------------------------------------------------------+
                                      |
       +-------------------------------------------------------------+
       | L5. PROJECT LAYER (Брифы съемок, тайминги, мудборды, локации)|
       +-------------------------------------------------------------+
                                      |
       +-------------------------------------------------------------+
       | L6. CLIENT LAYER (Частные заметки, брифы моделей, нюансы)    |
       +-------------------------------------------------------------+
```

## 2. 6 иерархических слоев (`KnowledgeLayer`)

| Слой | Описание и сфера применения | Примеры документов |
| :--- | :--- | :--- |
| **`GLOBAL`** | Общепринятая теория визуального искусства, оптики и колористики. | Цветовой круг Иттена, глубина резкости, правило третей, выдержка синхронизации. |
| **`PROFESSIONAL`** | Профессиональные методики, сетапы освещения, ретушь, работа с моделью. | Схема света «Бабочка» (Paramount), использование Beauty Dish с сотами, анатомия позы. |
| **`PERSONAL`** | Фирменный почерк, визуальная философия, ценности, творческий манифест. | «Почему я снимаю с мягким светом», «Мое отношение к ретуши кожи», эстетика кадра. |
| **`BUSINESS`** | Коммерческие регламенты, правила оплаты, тайминги, структура пакетов услуг. | Описание пакета «Премиум под ключ» (45 000 руб), условия бронирования студии, договор. |
| **`PROJECT`** | Контекст конкретной съемочной задачи или проекта. | Бриф лукбука бренда «Silk & Wool», тайминг съемочного дня, локация Artplay. |
| **`CLIENT`** | Персональные особенности, пожелания и референсы конкретных заказчиков. | Предпочтения Екатерины: холодные тона, акцент на украшения, табу на съемку справа. |

## 4. Сквозная трассируемость (`SourceTrace`)

Система исключает анонимные ответы. При ретривале каждый фрагмент знаний формирует объект трассировки:

```json
{
  "source_id": "8fa160c8-4721-4ba2-b258-3a9a5f47d911",
  "title": "Студийный свет: Схема Бабочка (Paramount Lighting)",
  "layer": "PROFESSIONAL",
  "chunk_id": "8fa160c8-4721-4ba2-b258-3a9a5f47d911-chk-1",
  "confidence": 0.95,
  "snippet": "Схема Бабочка: источник света ставится прямо перед моделью и чуть выше уровня глаз..."
}
```

Трассировка прокидывается в финальный ответ Brain API (`trace.knowledge_sources`) и отображается в интерфейсе клиента, позволяя пользователю видеть первоисточник любой рекомендации.

## 5. Классификация галлюцинаций (Zero Hallucination Policy)

Метод `evaluate_hallucination(query, retrieved_chunks, answer)` классифицирует сформированный ответ на 4 типа:

1. **`GROUNDED`:** ответ строго опирается на подтвержденные чанки из базы знаний (пересечение терминов $\ge 3$).
2. **`INFERENCE`:** ответ содержит логический вывод на базе знаний, но не цитирует их дословно.
3. **`GENERAL_KNOWLEDGE`:** ответ сформирован на базе общих знаний LLM при отсутствии профильных данных в базе.
4. **`UNKNOWN`:** в базе знаний факт отсутствует, и ассистент честно заявляет о недостатке информации.

### Правило отказа на неизвестных фактах:
Если запрос касается закрытых фактов (например, *"секретный код сейфа в фотостудии"* или *"точный номер паспорта ассистента"*), ретривал возвращает 0 чанков, а система формирует контролируемый отказ:
> *"В базе знаний информация о данном объекте не найдена."* (статус `UNKNOWN`).

## 6. Схема таблиц SQLite

```sql
CREATE TABLE IF NOT EXISTS knowledge_sources (
    source_id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    author TEXT,
    date TEXT,
    type TEXT NOT NULL,
    category TEXT NOT NULL,
    subcategory TEXT,
    tags_json TEXT,
    project TEXT,
    client TEXT,
    language TEXT DEFAULT 'ru',
    source_path TEXT,
    timestamp TEXT NOT NULL,
    confidence REAL DEFAULT 0.9,
    visual_description TEXT,
    ocr_text TEXT
);

CREATE TABLE IF NOT EXISTS knowledge_chunks (
    id TEXT PRIMARY KEY,
    source_id TEXT NOT NULL,
    layer TEXT NOT NULL,
    content TEXT NOT NULL,
    metadata_json TEXT NOT NULL,
    created_at TEXT NOT NULL,
    FOREIGN KEY(source_id) REFERENCES knowledge_sources(source_id)
);

CREATE INDEX IF NOT EXISTS idx_chunks_layer ON knowledge_chunks(layer);
CREATE INDEX IF NOT EXISTS idx_chunks_source ON knowledge_chunks(source_id);
```
