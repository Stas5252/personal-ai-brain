## ADR-001: Выбор Open WebUI в качестве базовой платформы персонального ассистента

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** Требовалось выбрать фундамент для персонального ассистента, способного закрыть функционал коммерческих решений типа «Яишки» (база знаний, адаптивная память, чат, мобильный доступ, мультимодальность, инструменты), соблюдая принцип максимального переиспользования зрелого open-source.
- **Рассмотренные альтернативы:** Dify, LibreChat, AnythingLLM, Open WebUI Computer, Hermes Agent, OpenClaw.
- **Решение:** Выбрать Open WebUI.
- **Последствия:**
  - *Плюсы:* Монолитный легковесный контейнер (1-2 GB RAM), встроенный RAG, встроенная долговременная память пользователя, поддержка любых провайдеров (OpenAI/Gemini/Ollama), мобильный PWA интерфейс, Python Functions прямо в браузере.
  - *Минусы:* Для Telegram потребуется легковесный микросервис-мост на этапе 2 (не является встроенным компонентом).

## ADR-002: Абстракция провайдера моделей через OpenAI-совместимый интерфейс

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** Архитектура не должна быть жёстко привязана к одной конкретной модели или вендору. Требуется поддержка горячей замены провайдера.
- **Решение:** Использовать стандартизированный протокол OpenAI Chat Completions (`OPENAI_API_BASE_URL` + `OPENAI_API_KEY`). В качестве первого провайдера подключен Google Gemini 2.5 (`https://generativelanguage.googleapis.com/v1beta/openai/`), используя переменные окружения.
- **Последствия:** В будущем добавление моделей OpenAI, Anthropic Claude, DeepSeek или локальных моделей (Ollama/vLLM) не потребует переделки пользовательского интерфейса, баз знаний или памяти.

## ADR-003: Выбор порта 8080 и бесконфликтное сосуществование с существующими проектами

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** На машине пользователя запущен проект `ars-*`, занимающий порты `3000, 5432, 6379, 8000, 8081, 8787, 9000, 9001`. Нельзя нарушать работу существующих контейнеров.
- **Решение:** Использовать порт `8080:8080`, который предварительно проверен и гарантированно свободен. Назначить явное имя проекта `personal-ai` в `docker-compose.yml`, исключающее конфликты имен из-за кириллического пути.
- **Последствия:** Никаких сетевых коллизий с существующими сервисами пользователя.

## ADR-004: Изоляция постоянных данных через именованный том `open-webui-data`

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** В Docker Desktop зарегистрировано более 20 томов других проектов. Нельзя перезаписывать или загрязнять чужие разделы.
- **Решение:** Создать независимый именованный том `open-webui-data`, управляемый Docker Compose манифестом.
- **Последствия:** Полная изоляция SQLite БД, документов и кэша Open WebUI. Безопасность при `docker system prune` или очистке других проектов.

## ADR-005: Выполнение эмбеддингов FastEmbed на CPU для сохранения VRAM

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** Видеокарта хоста (NVIDIA GeForce RTX 3070) имеет 8 GB VRAM.
- **Решение:** Для RAG-эмбеддингов текста использовать движок по умолчанию FastEmbed / Sentence-Transformers на CPU (10-ядерный i5-13400F справляется за миллисекунды).
- **Последствия:** Все 8 GB видеопамяти остаются свободными для будущих локальных LLM-моделей (например, Nous-Hermes-3-8B или Qwen-2.5-7B) или локального видео/фотомонтажа.

## ADR-006: Отказ от ранней кастомизации на этапе фундамента (Strict Scope Control)

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** Соблазн сразу писать Telegram-бота, кастомные пайплайны и агентов продаж.
- **Решение:** Строго следовать поэтапному подходу: на Этапе 1 только развёртывание, проверка тестов и фиксация стабильного фундамента. Все надстройки перенесены на последующие этапы.

## ADR-007: Фиксация стабильной версии Docker Image и безопасность секретов

- **Статус:** Принято (Approved)
- **Дата:** 2026-09-06
- **Контекст:** Использование плавающего тега `:main` создает риск нестабильности при автоматических обновлениях. Хранение секретов в репозитории создает риск компрометации.
- **Решение:**
  1. Зафиксировать образ на стабильном релизе: `ghcr.io/open-webui/open-webui:0.11.3` (дайджест `sha256:41daa0cf2561a5d4c8d1ff31ee2a98d93ab4d3ac2605cac69366ff6a3374a933`).
  2. Перевести `ENABLE_SIGNUP=false` после создания администратора.
  3. Все секреты изолировать в `.env`, исключенном из Git. Запретить вывод реальных значений ключей и паролей в логи, тесты и документацию.
- **Последствия:** Предсказуемое воспроизводимое окружение, защищенное от несанкционированной регистрации и утечки учетных данных.
