# Архитектурное сравнение платформ (Architecture Options Evaluation)

**Документ:** Оценка базовых платформ для персонального мультимодального AI-ассистента  
**Статус:** Завершено. Решение принято в пользу Open WebUI  
**Автор:** Principal AI Architect

---

## 1. Контекст и бизнес-требования

Проект направлен на создание персонального AI-ассистента уровня или выше коммерческого продукта «Яишка» (автоматизация креаторов, фотографов, продюсеров: сценарии, мудборды, анализ референсов, прайсы, продажи, базы знаний курсов, голосовой ввод, мобильный доступ, Telegram).

**Ключевой архитектурный принцип:**  
*Use existing mature open-source components first.* Не изобретать велосипед там, где сообщество уже создало стабильный, поддерживаемый и расширяемый фундамент.

## 3. Детальный разбор кандидатов

### 3.1. Open WebUI (Выбор №1 — Основа системы)
- **Сильные стороны:**
  - Монолитный легковесный контейнер на FastAPI + SvelteKit.
  - Поддержка абстракции любых LLM-провайдеров: OpenAI, Google Gemini, Anthropic, Ollama, OpenRouter.
  - Встроенный механизм долговременной памяти (Memories), автоматически сохраняющий контекст пользователя, предпочтения, стиль общения.
  - Встроенный RAG: поддержка документов любого типа, автоматическая векторизация и семантический поиск.
  - Механизм Functions/Pipes: возможность писать кастомные пайплайны на чистом Python прямо в веб-интерфейсе без необходимости перезапуска контейнера.
  - Нативная поддержка мобильных устройств (PWA) и голосового общения в реальном времени.
- **Ограничения:**
  - Отсутствует встроенный «из коробки» Telegram-клиент (решается отдельным микросервисом-адаптером на `aiogram` через стандартный REST API Open WebUI на следующем этапе).

### 3.2. Dify
- **Архитектурный вердикт:** Избыточен для персонального ассистента на текущем этапе.
- **Оценка:** Dify — великолепная платформа для конструирования enterprise-решений со сложными многошаговыми графами. Однако для персонального ассистента стек из 10 контейнеров (Postgres, Redis, Weaviate, Sandbox, Worker, API, Web, Nginx) создаёт неоправданный оверхед по памяти (4-8 GB) и усложняет сопровождение.

### 3.3. LibreChat
- **Архитектурный вердикт:** Сильный соперник, но уступает Open WebUI в RAG и расширяемости функциями.
- **Оценка:** Интерфейс LibreChat максимально приближен к ChatGPT, но требует связки MongoDB + Node.js + MeiliSearch + Python RAG API. Написание расширений требует изменения кода на Node.js или подключения внешних сервисов, тогда как в Open WebUI есть встроенный Python Sandbox (Functions).

### 3.4. AnythingLLM
- **Архитектурный вердикт:** Слишком узок функционально.
- **Оценка:** Отличное локальное приложение для общения с PDF, но слабо подходит для роли «второго пилота» с агентами, адаптивной памятью, сложными инструментами и голосовым взаимодействием.

### 3.5. Вспомогательные компоненты:
- **Open WebUI Computer:** Перспективный модуль для управления рабочим столом (OS automation). Будет исследован на этапе автоматизации ПК.
- **Hermes Agent:** Оптимальный выбор локальной модели (Nous-Hermes-3) для function calling и рассуждений при работе офлайн.
- **OpenClaw:** Инструмент для дата-майнинга и веб-скрапинга. Рекомендуется как внешний инструмент (Tool/Function) в Open WebUI для сбора референсов и трендов.

---

## 4. Итоговое архитектурное заключение

Платформа **Open WebUI** безоговорочно побеждает по совокупности критериев для роли персонального ядра AI-ассистента. Она объединяет в одном нетребовательном контейнере воркспейс, адаптивную память, базу знаний, мультимодальность и богатый API, позволяя подключить Telegram и кастомную логику на последующих этапах без переписывания фундамента.
