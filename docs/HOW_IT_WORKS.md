# Как работает Personal AI Brain

Документ описывает фактическое поведение кода в этом репозитории. Всё, что
требует ключа, внешнего сервиса или ручного шага, помечено явно. Здесь нет
обещаний «на будущее».

---

## 1. Знакомство: бот сначала узнаёт человека

Знакомство ведёт `src/brain/engines/profile_engine.py`. Есть два пути, оба
рабочие.

**Путь A — свободный рассказ.** Пользователь пишет о себе одним сообщением.
`extract_profile_from_freeform()`:

1. Просит модель вернуть JSON с полями профиля.
2. Если модель недоступна или ответила мусором, включается регулярный парсер:
   он вытаскивает имя, город и нишу из текста. Профиль всё равно сохраняется —
   просто с меньшим числом полей.
3. Сохраняет факты в память (`CORE_FACT`, `GOAL`).
4. Возвращает: `friendly_summary`, `missing_critical_fields`,
   `next_clarifying_question`, `is_complete`. Бот задаёт ровно один следующий
   вопрос, а не допрашивает анкетой.

**Путь B — анкета из 10 вопросов.** `start_onboarding()` /
`answer_onboarding()` ведут по списку: имя, ниша, город, услуги, цены,
аудитория, визуальные предпочтения, тон и стиль продаж, стоп-слова, цели.
Сессия хранится в таблице `onboarding_sessions`, профиль — в `user_profile`.
Прогресс не теряется при перезапуске контейнера.

Профиль после этого используется **везде**: в контенте, продажах, стратегии
продвижения и в промпте генерации изображений (ниша, город, визуальный стиль,
стоп-слова).

## 2. Память: что запоминается и как достаётся

Движок — `src/brain/engines/memory_engine.py`, хранилище — SQLite.

**Приём информации** (`evaluate_admission`) — детерминированные правила, без
вызова модели:

| Что сказал пользователь | Тип памяти | Важность |
| --- | --- | --- |
| «люблю плёночный свет», «не снимаю…» | `PREFERENCE` | 0.95 |
| «клиент Анна, съёмка 12 мая» | `CLIENT` / `PROJECT` | 0.85 |
| «я снимаю семьи в Самаре» | `PROFILE` | 0.90 |
| «завтра встреча» | `TEMPORARY` (живёт 24 часа) | — |
| прочие содержательные фразы | `FACT` | 0.50 |
| «ок», «спасибо», короткие реплики | не сохраняется | — |

**Разрешение конфликтов.** Новый факт, противоречащий старому, не удаляет
старый: прежняя запись получает статус `SUPERSEDED`, история остаётся.

**Извлечение** (`retrieve_relevant_memories`) — взвешенная формула:
`0.50 × релевантность + 0.30 × важность + 0.20 × свежесть`, период полураспада
свежести 30 дней. Есть словарь синонимов доменов, поэтому «клиентка» находит
записи про «клиента».

Честное ограничение: любое содержательное сообщение длиной от 8 символов
сохраняется как `FACT`. База растёт быстро. Чистка — `/забудь` и
`scripts/cleanup_test_data.py`.

## 3. Каналы

| Канал | Файл | Состояние |
| --- | --- | --- |
| Telegram (основной) | `channels/telegram_guided_runner.py` | рабочий, long polling |
| HTTP API | `api/app.py` | рабочий, ключ `BRAIN_API_KEY` обязателен |
| Web Studio | `/` и `/studio` | рабочий |
| Open WebUI | `api/routes/openai_routes.py` | рабочий, OpenAI-совместимый |
| MAX | `channels/max_adapter.py` | **транспорта нет**, только заглушка интерфейса |

Доступ к Telegram-боту ограничен `TELEGRAM_OWNER_ID`: чужие сообщения
игнорируются.

Пока бот думает, в чате виден статус «печатает…», а при генерации картинки —
«отправляет фото». Статус живёт до конца задачи, а не 5 секунд
(`channels/telegram_media.py`).

## 4. 34 функции по кнопкам

Меню: **Контент · Продажи · Съёмки · Продвижение**. Реестр — один файл
`services/guided_actions.py`, клавиатуры — `channels/bot_config.py`; тест
`tests/brain/test_guided_actions.py` падает, если списки разошлись.

Логика любой кнопки одинакова:

1. Кнопка нажата → если нужны данные, бот задаёт конкретный вопрос и
   запоминает шаг (переживает перезапуск).
2. Пользователь присылает текст, голосовое или фото. Голос распознаётся
   локально, фото читается vision-моделью.
3. Результат считает профильный движок, а не «универсальный промпт».
4. Временные файлы удаляются всегда, даже при ошибке.

Жёсткие правила против выдумок:

- **Прайс-лист** не создаётся без базовой цены — бот запросит её.
- **Анализ конкурентов** отказывается работать без присланных материалов и
  всегда помечает: живые аккаунты не просматривались.
- **Отзывы** требуют реальный текст; цитата не переписывается.
- **Локации и фотодень** не выдумывают адреса, даты и слоты.
- **Треки** сопровождаются напоминанием проверить лицензию.

## 5. Генерация и перерисовка фото

Движок — `src/brain/engines/image_engine.py`. Две кнопки в разделе «Съёмки»:
🎨 «Сгенерировать фото» и ♻️ «Перерисовать кадр». Тот же движок доступен по
HTTP: `POST /brain/image`, файл скачивается через `GET /brain/image/{файл}`.

Что происходит:

1. **Сборка промпта.** Детерминированный каркас из брифа и профиля: ниша,
   город, визуальный стиль, стоп-слова, запрет текста, логотипов и водяных
   знаков, запрет узнаваемых людей и чужих торговых марок. Модель может
   обогатить формулировку; если она недоступна или ответила слишком коротко,
   используется каркас.
2. **Запрос** к `generateContent` с ключом `GEMINI_API_KEY`. Модель по
   умолчанию — `gemini-2.5-flash-image`, при 400/404 пробуется следующая из
   `BRAIN_IMAGE_FALLBACK_MODELS`.
3. **Проверка байтов.** base64 декодируется строго, затем проверяется сигнатура
   PNG/JPEG/WebP. HTML-страница с ошибкой не может быть сохранена как `.png`.
4. **Сохранение** в `BRAIN_GENERATED_DIR` с уникальным именем.
5. **Отдача.** Telegram присылает настоящий файл фотографией с подписью. Если
   отправка не удалась, бот сообщает об этом и даёт путь к файлу — молчаливой
   потери результата нет.

Перерисовка дополнительно прикладывает исходное фото (до 12 МБ) и требует
сохранить геометрию кадра и узнаваемость героя.

Если ключа нет или модель отказала, ответ выглядит так:

> ⚠️ Изображение не создано. Причина: GEMINI_API_KEY не задан…

Никаких «вот ваша картинка» без картинки, никаких выдуманных ссылок и
картинок-заглушек.

## 6. Где используется модель, а где нет

`use_llm` — настоящий переключатель, а не декоративный аргумент.

- `use_llm=False` — только детерминированный шаблон, ноль сетевых вызовов.
- `use_llm=True` — модель может переписать формулировки существующих полей.
  Она **не может**: менять типы, добавлять поля и трогать защищённые ключи
  (`measurement_note`, `evidence_scope`, `permission_note`, `proof_needed`,
  `observations`, `quote`, `stories`, `goal`).
- Если модель недоступна или вернула не-JSON, возвращается шаблон.
- После трёх подряд неудач вызовы приостанавливаются на 5 минут, чтобы не
  долбить мёртвый эндпоинт, затем автоматически возобновляются.

## 7. Что нужно для запуска

| Возможность | Требование |
| --- | --- |
| Текстовые функции, чат | `GEMINI_API_KEY` |
| Генерация и перерисовка фото | `GEMINI_API_KEY` + доступ к image-модели |
| Разбор фото (vision) | `GEMINI_API_KEY` |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID` |
| HTTP API | `BRAIN_API_KEY` |
| База знаний курса | корпус в `материалы для ии`, индексация при старте |

Запуск: `docker compose up -d` (сервисы `api`, `telegram`, `open-webui`).
Проверка: `GET /health`, `GET /health/ready`, `GET /health/knowledge`.

## 8. Чего система не делает

Честный список, чтобы никто не ждал несуществующего:

- Не смотрит живые аккаунты Instagram и не знает охваты — аналитика только по
  тому, что прислали.
- Не публикует посты и не ведёт соцсети автоматически.
- Не принимает оплату и не бронирует даты в календаре.
- Не даёт юридических заключений: договор — это чек-лист и вопросы к юристу.
- MAX-канал не подключён к транспорту.
- Многопользовательский режим и биллинг не реализованы: бот рассчитан на
  одного владельца.
